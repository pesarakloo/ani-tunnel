# آنی تانل — ani tunnel

مدیریت تونل ایران و خارج با پنل وب، منوی ترمینال، مانیتورینگ تلگرام و بازیابی خودکار اتصال.

[کانال @xray_chrome](https://t.me/xray_chrome) · [دانلود نسخه‌ها](https://github.com/pesarakloo/ani-tunnel/releases) · [English](README.md)

## نصب و به‌روزرسانی

دستور زیر را با کاربر `root` روی **هر دو سرور ایران و خارج** اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/pesarakloo/ani-tunnel/main/install.sh)
```

بازکردن منوی مدیریت:

```bash
sudo ani-tunnel
```

نصب‌کننده نسخهٔ مناسب معماری سرور را دریافت و SHA256 را بررسی می‌کند. قبل از جایگزینی، فایل اجرایی جدید را آماده می‌کند و از فایل اجرایی قبلی و تنظیمات نسخهٔ پشتیبان می‌گیرد. سپس فقط سرویس‌هایی را که فعال بوده‌اند راه‌اندازی مجدد می‌کند. اگر راه‌اندازی سرویس خطا بدهد، فایل اجرایی قبلی برگردانده می‌شود. موفقیت شروع سرویس، تضمین عبور ترافیک نیست؛ اتصال تونل را هم بررسی کنید.

نسخهٔ پشتیبان در مسیر زیر ذخیره می‌شود؛ مسیر دقیق هنگام نصب نمایش داده می‌شود:

```text
/root/BackPack/backups/ani-*
```

برای حفظ نصب قبلی، تنظیمات در `/etc/backpack` و نام سرویس‌ها با پیشوند `backpack-` باقی می‌مانند. دستور `ani-tunnel` به فایل اجرایی `/usr/local/bin/backpack` اشاره می‌کند. توکن‌ها، پورت‌ها، لینک‌های راه‌اندازی و رمز پنل با نصب مجدد پاک نمی‌شوند.

### نصب از سورس

اگر هنوز اولین Release منتشر نشده یا می‌خواهید همین سورس نصب شود:

```bash
git clone https://github.com/pesarakloo/ani-tunnel.git
cd ani-tunnel
sudo BP_BUILD_FROM_SOURCE=1 bash install.sh
```

برای ساخت به Go نسخهٔ 1.26.9 یا جدیدتر نیاز است. نصب‌کننده می‌تواند ابزار موردنیاز را نصب کند.

### نصب آفلاین

از یک Release، فایل `install.sh`، فایل `SHA256SUMS` و آرشیو متناسب با معماری سرور را دریافت کنید. برای بیشتر VPSها فایل `ani-tunnel_linux_amd64.tar.gz` مناسب است؛ برای ARM64 فایل `ani-tunnel_linux_arm64.tar.gz` را بگیرید. هر سه را در پوشهٔ خصوصی مانند `/root/ani-install` قرار دهید:

```bash
cd /root/ani-install
sha256sum -c SHA256SUMS --ignore-missing
bash install.sh
```

## رفع اختلال اتصال

یک باگ قابل بازتولید در TCP و WebSocket اصلاح شده است: با قطع اتصال کنترل، اتصال‌های دادهٔ بی‌کار و ظرفیت مصرف‌شدهٔ آن‌ها آزاد نمی‌شدند. تکرار این وضعیت می‌توانست منابع را اشغال کند و تونل تا ری‌استارت سمت ایران از کار بیفتد.

در این نسخه، اتصال داده به همان کلاینتی وابسته است که آن را ایجاد کرده است. قطع یا جایگزینی کلاینت، اتصال‌ها و سهم آن‌ها از محدودیت اتصال را آزاد می‌کند. همچنین در TCP و WS/WSS، پاسخ RTT دوره‌ای بررسی می‌شود تا اتصالی که فقط ظاهراً باز است شناسایی شود؛ مهلت پاسخ در شرایط عادی ۳۰ ثانیه است.

این باگ با آزمون بازتولید شده و اصلاح آن بررسی شده است. چون لاگ و تنظیمات سرور دارای اختلال در اختیار نیست، نمی‌توان همهٔ علت‌های اختلال آن سرور را به همین مورد محدود دانست. نتیجهٔ آزمون‌ها در [VALIDATION.md](VALIDATION.md) آمده است.

## شروع کار

۱. برنامه را روی هر دو سرور نصب کنید.
۲. برای تونل معکوس، سمت ایران را Server و سمت خارج را Client بسازید.
۳. نوع تونل، توکن و پورت ارتباطی دو سمت باید با هم سازگار باشند.
۴. پورت ورودی ایران را به سرویس موردنظر در خارج نگاشت کنید.
۵. وضعیت و عبور ترافیک را از پنل یا ترمینال بررسی کنید.

```bash
ani-tunnel version
ani-tunnel tunnel list
ani-tunnel check -c /etc/backpack/your-tunnel.toml
journalctl -u backpack-your-tunnel.service -n 150 --no-pager
```

پنل وب، صفحهٔ ورود، تأیید دومرحله‌ای، آیکن‌ها، منوی ترمینال و پیام‌های تلگرام با نام ani tunnel و کانال `@xray_chrome` شخصی‌سازی شده‌اند. گزارش اشکال را در [Issues همین مخزن](https://github.com/pesarakloo/ani-tunnel/issues) ثبت کنید.
